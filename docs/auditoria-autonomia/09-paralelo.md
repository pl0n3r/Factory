# C2 · Auditoría de cuatro agentes en paralelo sin colisiones

> **Hoja:** [Factory #2130](https://github.com/pl0n3r/Factory/issues/2130) · **Épica:** [#2121](https://github.com/pl0n3r/Factory/issues/2121) · **Corte:** 23-nov-2026 (UTC), [Factory/main@d99c5220](https://github.com/pl0n3r/Factory/commit/d99c5220f53db23c419c0f8f74f71eaec1cbc776). **Roles:** SRE (primario) y QA (contraste). **Tipo:** auditoría documental supervisada, no experimento de cuatro workers.

## Veredicto y condición de entrada

**Cuatro agentes autónomos operando simultáneamente: NO DEMOSTRADO.** Hay contratos y tests de claims disjuntos, coordinación V3 real *después de* `/tomar` humano y merges de PR supervisados. No existe en la evidencia examinada un conjunto correlacionado de cuatro `runner_id`, órdenes recibidas, ACK, heartbeat simultáneo fresco, ejecución independiente de herramientas/Qwen, cuatro PR sin duplicados, serialización de sus merges y continuación sin otro prompt.

**La dependencia administrativa no equivale a éxito operativo C1.** [#2129](https://github.com/pl0n3r/Factory/issues/2129) está CLOSED/completed y su [PR #2194](https://github.com/pl0n3r/Factory/pull/2194) fue fusionado; el dueño declaró [C2 liberada para trabajar la hoja](https://github.com/pl0n3r/Factory/issues/2130#issuecomment-7092153307). Sin embargo, [C1/08-prueba-ciclo.md](08-prueba-ciclo.md) concluye **NO DEMOSTRADO**: no se acreditó trigger → orden Qwen ni edición+test real por Qwen Code. Por eso la autorización de redactar esta auditoría **no habilita** lanzar cuatro agentes reales, activar ControlBot/FactoryRunner ni afirmar una aceptación C2 positiva.

**Semántica:** VERIFICADO = un hecho delimitado con fuente primaria; PARCIAL = contrato o prueba de un tramo, no integración; BLOQUEADO = guarda o fallo concreto; NO IMPLEMENTADO = ausencia observada *en superficie delimitada*, no en todo el ecosistema; NO DEMOSTRADO = no hay prueba suficiente. Los estados describen el atributo señalado, no un porcentaje de autonomía.

### Diferencia entre cuatro leases y cuatro agentes

Cuatro Issues con paths compatibles, cuatro simulaciones, cuatro ventanas de ChatGPT o cuatro éxitos de CI pueden mostrar **coordinación parcial**, pero no una ejecución de **cuatro trabajadores autónomos simultáneos**. Para C2, cada corrida debe aportar la cadena `issue_id → reservation_id → order_id → runner_id → process/session → tool-execution → test → head_sha → PR → merge_sha` con instante UTC, fuente autenticada y correlación estable. La simultaneidad requiere intervalos de heartbeat/ejecución solapados **en un mismo corte**. No sustituir logs ausentes por PRs de otros agentes o reconstrucciones manuales.

## Prueba falsable para una C2 positiva (NO ejecutada aquí)

1. **Preflight:** C1 verificable de verdad, #767 RUNNING, cuatro hojas existentes y listas con deps terminadas, claims disjuntos y sin freeze, respaldo/consentimiento/autoridad aplicables. Snapshot canónico completo de siete repositorios y SHA/policy exactos; si falta alguno, cero envíos. Un cierre administrativo de #2129 por sí solo no es evidencia C1.
2. **Asignación y aislamiento:** un disparador no manual entrega cuatro órdenes autenticadas a cuatro `runner_id` únicos y cuatro reservas V3 activas únicas; registrar `order_id`, `lease_id`, fingerprints de aceptación/tarea, `issued_at` y destinatario. Negativos: mismo claim en dos leases, owner inválido, dependencia abierta, `policy_sha` obsoleto y replay deben fallar cerrados sin iniciar otro worker.
3. **Trabajo observable:** recoger cuatro procesos/sandboxes realmente distintos, heartbeats frescos, poll/ACK y resultados durables por orden. Cada agente efectúa una edición real de fixture sintético y deja test RED→GREEN + diff/commit atribuible; si Qwen Code devuelve exit 55, no sumar ese trabajo como completado.
4. **Fallo/reanudación:** inyectar corte de transporte y reinicio de un worker durante la prueba; verificar que la orden/ACK/evento mantienen identidad, que no hay doble ejecución, PR duplicado ni pérdida de claims. Rechazar `runner_id` falso, token inválido, evento stale/fuera de orden o heartbeat antiguo.
5. **Integración serial y continuidad:** abrir cuatro PR distintos con su V3, correr `Validar`/CodeQL/Sonar exact-HEAD y CodeRabbit FINAL como máximo una vez por PR definitivo. Fusionar estrictamente de uno en uno; recalcular `main`, conflictos, protección, HEAD y checks para cada sucesor. Exigir recibo final de las cuatro fusiones, reservas liberadas y siguiente despacho sin comando humano.
6. **Criterio negativo global:** si falta cualquier identidad, intervalo simultáneo, evidencia de herramienta efectiva, test, run, SHA de merge o siguiente selección, resultado C2 **NO DEMOSTRADO/BLOQUEADO**, aunque todos los mocks sean verdes. No crear un fixture o declarar manualmente `VERIFICADO` para compensarlo.
