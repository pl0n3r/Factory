# Auditoría de autonomía A5: Qwen local, herramientas y salida 55

> **Corte de evidencia:** 12 de noviembre de 2026 (UTC). **Hoja:** [Factory #2126](https://github.com/pl0n3r/Factory/issues/2126), épica [#2121](https://github.com/pl0n3r/Factory/issues/2121). **Alcance:** diagnóstico documental, no prueba nueva sobre el Mac del propietario ni ejecución de Qwen en esta sesión.

## Criterio de lectura y niveles de ejecución

**VERIFICADO** demuestra **solo** el atributo, entorno y fecha de un recibo concreto; **PARCIAL** acredita una subcapacidad o ejecución supervisada, pero no el objetivo completo; **BLOQUEADO** identifica un impedimento observado o una puerta de autoridad vigente; **NO IMPLEMENTADO** exige prueba de ausencia de implementación, no meramente falta de logs; **NO DEMOSTRADO** significa que no hay recibo suficiente de ejecución real. Cada estado de esta hoja se limita a la evidencia enlazada y **no** acredita que la configuración siga vigente hoy.

- **Manual GPT/Claude:** una persona usa asistentes para decidir y ejecutar pasos, incluidos GitHub y los tests. No es autonomía del sistema.
- **Automatización supervisora:** revisa issues, reporta estados, propone decisiones o monitoriza runs; no ejecuta la hoja.
- **Ejecución supervisada:** un operador obtiene la V3, invoca inferencia o scripts, inspecciona/aplica cambios, prueba y lleva el PR a merge.
- **Ejecución autónoma Qwen:** el propio ejecutor conectado a Qwen recibe una tarea legítima, usa **tool calls efectivas** para editar/probar, materializa commit/PR con su V3, satisface CI/seguridad y continúa el flujo sin que GPT/Claude o el dueño realicen los pasos por él. **No está demostrado.**

La fuente de partida es el historial [Factory #2067](https://github.com/pl0n3r/Factory/issues/2067), contrastado con PRs y commits efectivamente fusionados. Las descripciones de pruebas del Mac son **recibos históricos publicados en comentarios**, no logs de ejecución reproducidos aquí; cuando no existe artefacto independiente, esa limitación permanece explícita.

## Qué significa realmente `exit 55`

**Causa inmediata observada: límite de tiempo del propio Qwen Code CLI, `FatalBudgetExceededError`.** No es un código que por sí solo identifique credenciales, GitHub, permiso de escritura o modelo averiado. Una reproducción mínima devolvió `exit=55`, ~29 s, stdout vacío y ese error tras `--max-wall-time 28s`, mientras Ollama respondió directamente en menos de un segundo ([recibo](https://github.com/pl0n3r/Factory/issues/2067#issuecomment-6711836970)). La generación real de archivos expiró incluso con 240 s ([recibo](https://github.com/pl0n3r/Factory/issues/2067#issuecomment-6714365571)). Con `--max-wall-time 90s` y sin herramientas, sí completó `QWEN_CLI_OK` ([recibo](https://github.com/pl0n3r/Factory/issues/2067#issuecomment-6714223963)).

**Causa subyacente más probable, todavía no aislada de forma definitiva:** la combinación Qwen Code 0.26.9 + `qwen3:4b` + backend OpenAI-compatible de Ollama no produjo el formato de llamada de herramienta que necesita el CLI dentro del presupuesto de generación/tiempo. En una prueba controlada, la API **nativa** con `think:false` produjo una llamada; el endpoint compatible agotó tokens razonando y no la produjo. Al ajustar el CLI a `reasoning:false`, `extra_body`, `edit` y autorización `auto-edit` persistió `exit 55`. Por tanto, la hipótesis de que **solo** desactivar reasoning basta queda refutada en la configuración ensayada ([comparación](https://github.com/pl0n3r/Factory/issues/2067#issuecomment-6724080966), [retest](https://github.com/pl0n3r/Factory/issues/2067#issuecomment-6724413535)).

**Descartes limitados por evidencia:** el modelo/servicio no estaban completamente caídos durante los controles directos; la falta de saldo GitHub no era la causa del ensayo aislado de edición; el test fallido no fue corregido por una herramienta efectiva; el JSON textual de `qwen2.5-coder:1.5b` no es `tool_calls`. **Sin logs internos del adaptador del CLI en una sesión autorizada, no puede asignarse causalidad única** entre proveedor, parsing de herramientas, inicialización/contexto, memoria, límites de generación, configuración de autorización o versión. Estado de causa profunda: **PARCIAL**. Estado de edición autónoma: **BLOQUEADO**.

## Reproducción y discriminadores que faltan

La evidencia histórica proporciona tres controles distintos. No repetirlos en repositorios de producto ni confundir el resultado de shell/pipeline con el exit status real del proceso:

1. **Inferencia mínima:** prueba headless sintética con `--max-tool-calls 0` y presupuesto de 90 s, `QWEN_CLI_OK` y exit 0. Es un control positivo, no aceptación E2E.
2. **Edición en laboratorio descartable:** archivo con `triple(7)=14`, test que espera 21, CLI con herramienta real registrada `edit`, auto-edit limitado al directorio temporal y un presupuesto acotado. Control observado: `exit 55`, archivo idéntico, test rojo. El objetivo de un fix sería **tool call ejecutada**, diff exacto y test que pase **sin intervención de otro agente**.
3. **Diferencial protocolo:** misma función sintética en Ollama nativo (`/api/chat`) y compatible (`/v1/chat/completions`), normalizando `think`, `max_tokens`, herramientas y `tool_choice`. Registrar mensajes estructurados, tiempo, `finish_reason`, tokens y si el CLI **ejecuta** la llamada. No aceptar texto que describa `edit` como ejecución real.

Para aislar la raíz faltan: versión/configuración vigente (sin tokens), protocolo exacto y parser usado por el CLI, logs saneados de solicitud/respuesta/herramientas, tiempo y memoria por etapa, prueba de un adaptador compatible con `tool_calls` reales, y repetición exit 0 con edición + unittest. Al revertir una eventual corrección, **el mismo test E2E de herramienta deberá fallar**; de lo contrario no hay regresión probatoria de AC-02.
