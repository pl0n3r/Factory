# Auditoría A4: FactoryRunner, workers y ejecución autónoma

**Corte:** 2026-11-12. **Epíca:** [Factory #2121](https://github.com/pl0n3r/Factory/issues/2121). **Hoja:** [Factory #2125](https://github.com/pl0n3r/Factory/issues/2125). **FactoryRunner analizado:** [`main@e80942554edec355a1cd258175e11941151feba1`](https://github.com/pl0n3r/FactoryRunner/commit/e80942554edec355a1cd258175e11941151feba1). **Factory base de la hoja:** `main@3239737cd040b222786f9d9003cbc92bbfb96231`.

## Dictamen y frontera de evidencia

**No está demostrado que haya un worker FactoryRunner activo y autónomo que reciba trabajo auténtico de ControlBot, invoque Qwen u otro agente, ejecute herramientas, prepare un PR y continúe con otra tarea sin intervención humana.** Eso **no** demuestra que no exista ningún proceso externo: GitHub y el repositorio no aportan un roster, heartbeat firmado y fresco, logs de una orden real o un PR trazado a tal worker.

Sí existe **software offline de ejecución y pruebas con mocks** en el árbol de FactoryRunner. La diferencia es comprobable en [`src/main.ts`](https://github.com/pl0n3r/FactoryRunner/blob/e80942554edec355a1cd258175e11941151feba1/src/main.ts), [`scripts/run-runner.ts`](https://github.com/pl0n3r/FactoryRunner/blob/e80942554edec355a1cd258175e11941151feba1/scripts/run-runner.ts) y [`tests/e2e-controlbot-mock.test.ts`](https://github.com/pl0n3r/FactoryRunner/blob/e80942554edec355a1cd258175e11941151feba1/tests/e2e-controlbot-mock.test.ts). No se ejecutaron comandos contra un servidor/worker real ni se leyeron secretos, sesiones o datos personales en esta auditoría.

**Regla de clasificación:** VERIFICADO = evidencia verificable del alcance descrito, nunca implicación automática de live; PARCIAL = código o pruebas de parte del recorrido sin prueba extremo a extremo real; BLOQUEADO = hay dependencia/puerta explícita; NO IMPLEMENTADO = falta una función requerida en la superficie examinada; NO DEMOSTRADO = no se obtuvo un recibo primario suficiente. Estos estados no se suman ni se convierten a porcentaje.

- [FactoryRunner Action #43211036518](https://github.com/pl0n3r/FactoryRunner/actions/runs/43211036518), workflow **«Observación local de reservas V3 (Fase A, solo lectura)»**, `completed/success` en SHA fuente `e8094255…`, evento `schedule`. Su job **«Observar únicamente el repositorio llamador»** terminó correctamente. **Tipo:** supervisión/observación automática de reservas, **no** ejecución de órdenes de un worker.
- [FactoryRunner Action #43207476627](https://github.com/pl0n3r/FactoryRunner/actions/runs/43207476627), **«Coordinación»**, `completed/success` en el mismo SHA fuente, evento `schedule`. Jobs de barrido/validación operativa y sincronización: **coordinación**, no un recibo de modelo ejecutor.
- Ambos workflows muestran actividad de GitHub Actions, **no** un proceso de FactoryRunner con identidad, heartbeat, orden, adapter y PR asociados. La lista no demuestra que sea imposible que exista un runner externo; solo que la evidencia consultada no lo acredita.
- [FactoryRunner #1](https://github.com/pl0n3r/FactoryRunner/issues/1) está **CLOSED**, con contratos implementados; [#607](https://github.com/pl0n3r/FactoryRunner/issues/607) sigue **OPEN/BLOQUEADO**, y [ControlBot #625](https://github.com/pl0n3r/ControlBot/issues/625) no acredita ControlBot conectado y operativo. Estos estados no equivalen a un ciclo completo de ejecución real.

## Bloqueos, autoridad exacta y correcciones

1. **Autorización humana y frontera del entorno:** [instrucción OWNER FactoryRunner #465/#6128276777](https://github.com/pl0n3r/FactoryRunner/issues/465#issuecomment-6128276777): «Sin trabajo nuevo hasta que se decida el go-live». [#431/A](https://github.com/pl0n3r/FactoryRunner/issues/431) solo habilitó preflight offline. Para conectar un worker/ControlBot/Hostinger reales hace falta una **decisión específica posterior del propietario**, identificación de operador, origen de órdenes, permisos, privacidad/consentimiento, custodia de secretos, restricciones de hosting, presupuesto si aplica y autorización separada de publicación o ejecución real.
2. **Observabilidad auténtica:** [FactoryRunner #606](https://github.com/pl0n3r/FactoryRunner/issues/606) necesita fuente read-only autorizada y comprobantes recientes de `runner_id`, capacidad y heartbeat; sin ella **no es posible** concluir «hay N workers». No debe falsificarse READY con un mock.
3. **Recuperación antes de operar:** [FactoryRunner #607](https://github.com/pl0n3r/FactoryRunner/issues/607) exige backup restaurado, rollback y RPO/RTO medidos en entorno autorizado; pruebas sintéticas no cumplen este gate. D-043/D-059 conservan requisitos de evidencia productiva terminal.
4. **Integración/ejecución técnica aún no acreditada:** cuando haya autoridad, hoja(s) acotadas **en FactoryRunner** con AC, V3, claims y regresión que fallen al revertir para conectar transporte real, agente/adapter autorizado, evidencia orden/ACK/evento, tests y PR. El diagnóstico Qwen/`exit 55` se investiga en [Factory #2126](https://github.com/pl0n3r/Factory/issues/2126), sin invadir su ruta.
5. **Prueba de autonomía:** un ciclo con referencia de orden ControlBot, identidad de runner y heartbeat frescos, registro de invocación del agente sin contenido sensible, hashes de cambios, tests ejecutados, PR y merge exact-HEAD; después una segunda orden iniciada sin intervención humana. [Factory #2129](https://github.com/pl0n3r/Factory/issues/2129) y [#2130](https://github.com/pl0n3r/Factory/issues/2130) son los contratos posteriores. No iniciar 4 workers antes de demostrar 1.

**Cambios de código aplicados en este PR:** ninguno. Por tanto no se afirma una nueva regresión de runtime que falle al revertirse; cada reparación futura requiere su test de regresión en el repositorio propietario. Este PR solo incorpora diagnóstico trazable en Factory, sin alterar FactoryRunner, decisiones, credenciales, branches ajenas ni ejecución operativa.

## Aceptación, límites y reversión

- **AC-01:** matriz con clasificaciones y enlaces verificables arriba; los vacíos permanecen NO DEMOSTRADO, no aprobados por inferencia.
- **AC-02:** no se corrige código fuera de esta ruta documental; la autorización exacta requerida y las hojas de corrección se identifican sin crear issues duplicados. Ningún dato personal ni secreto incluido.
- **AC-03:** `Tests de scripts`, `Validar` y `CodeQL` deben acreditarse terminales y verdes para el HEAD del PR antes de fusionar; un resultado aún pendiente **no se declara éxito**.

**Riesgo:** bajo, solo Markdown. **Reversión:** revertir el squash del PR. **No aplica DoD de UI/negocio:** no cambia interfaces ni endpoints de producto. **Fuera de alcance:** deploy, activación Hostinger, configuración de credenciales, pruebas con usuarios reales, lanzamiento de procesos locales no autorizados, cambios de fase, alteración de políticas/CI y cierre del gate de autonomía por la sola existencia de esta auditoría.
